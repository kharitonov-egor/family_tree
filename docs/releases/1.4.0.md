Family Tree runs on Minecraft 26.4 with Fabric. It needs Fabric API for 26.4, Fabric Loader 0.20.1 or newer, and Java 25.

| Minecraft | Fabric | NeoForge | Forge | Java |
| --- | --- | --- | --- | --- |
| 26.4 | Fabric API for 26.4 | No build yet | No build | 25 or newer |

- History carries over. A 26.3 world opened in 26.4 keeps every pet, parent, death, custom name, and horse stat, because 26.4 reads the same `familytree.dat` file.
- Every feature of the 26.3 build works on 26.4: the browser, trees, model portraits, PNG export, horse stats, the chest menus for players without the mod, and Mod Menu's Configure button.
- Jade, JourneyMap, and Xaero's Minimap had no 26.4 builds when this file was built, so their tooltips and waypoints on 26.4 are untested.

## See relatives in the world

Hold the grave accent key (`` ` ``, left of 1) and look at an animal Family Tree records. Its relatives that are loaded nearby glow on your screen, each with a label such as "Parent · Comet", "Child · Ember", or "Half sibling · Pip". The animal you look at glows white with a ◆ before its name, and dust particles flow along a line from each parent to it and from it to each child. Look at another animal while you hold the key to switch to its family. The action bar says how many relatives are nearby.

- Labels name parents, children, siblings, half siblings, grandparents, and grandchildren, using the same relationships as the breeding planner. Minecraft animals have no sex, so the words are neutral: parent rather than mother, sibling rather than sister. Aunts, uncles, and cousins stay unlit, so a pen of one large family doesn't light up whole.
- Each relation has its own color from the Okabe-Ito palette, which stays distinguishable with the common kinds of color blindness: orange parents, yellow grandparents, sky-blue children, purple grandchildren, and green siblings. The label always names the relation, so color is never the only cue.
- The outlines, labels, and lines exist only on your screen. Other players see nothing.
- The server decides who is related and applies the same `viewPolicy` as the Family Tree screens. Another player's pet that you can't open in Family Tree stays unlit, and so do relatives reached only through it. The server answers with the relatives loaded within 64 blocks of you, at most 32 of them, by entity ID and never by position.
- Holding the key sends a request only when you look at an animal it hasn't asked about, at most four a second, and the server turns away faster requests before it looks anything up. Answers are kept until you let go and refreshed every five seconds while you keep looking.
- Settings has two new switches. **Relatives in the world** turns the key off completely, with no requests and no outlines. **Lines to parents and children** hides the particle lines. Change the key under Options > Controls > Family Tree. The default is free in vanilla Minecraft, Jade, JourneyMap, Xaero's Minimap, JEI, REI, and EMI. On NeoForge and Forge the key only works in the world, so it doesn't clash with keys that recipe viewers use in inventory screens.
- The lines show even with Particles set to Minimal.
- Server owners can deny the `familytree.relatives` permission node to turn the key and the menu button off, and `relativesCooldownMillis` in `config/familytree-server.properties` sets the request cooldown, 200 ms by default.
- On a server without Family Tree, or with Family Tree 1.3.0 or older, the key shows a short message in the action bar and nothing else changes. The rest of Family Tree works with a 1.3.0 server as before.

The key uses two new optional channels, `relatives_request_v1` and `relatives_result_v1`. NeoForge and Forge still register protocol 4, so a 1.4.0 client still joins a 1.3.0 server. In testing, Fabric 26.3 and NeoForge 1.21.1 clients joined 1.3.0 servers, showed the message for the key, and opened the Family Tree screens normally. No saved fields change.

## Breeding planner

Pick two animals and Family Tree shows what their foal can be before you feed them. Choose **Breeding planner** at the top of the browser, or select an animal in the tree and choose **Plan breeding**. To plan a pair you are looking at in the tree, Shift-click the second card first.

- For horses, donkeys, mules, llamas, and trader llamas, each foal stat gets its lowest, most likely, and highest value, a bar showing how likely each value is, and the chance the foal beats both parents. Speed is in blocks per second, jump in blocks, and health in hearts. Llamas show chest slots first.
- The odds come from Minecraft's own breeding code, read from every supported version from 1.20.1 to 26.4. All of them use the same rule: a foal's stat lands around its parents' average, spread by the gap between the parents plus 30% of the stat's whole range, and a value past the game's limit bounces back inside it. Family Tree computes those chances exactly instead of guessing from samples.
- A llama foal's strength is a random number from 1 up to the stronger parent's strength, with a 3% chance of one more. The weaker parent doesn't matter, and only that 3% roll can beat the stronger parent.
- Every camel has the same stats, so the planner says so instead of showing ranges.
- A horse and a donkey plan a mule. A llama and a trader llama can have either kind of foal, depending on which parent's breeding code runs.
- The planner warns when a parent was born in the last two days and may still be a foal.
- The planner works from the family list the client already receives, so it adds no saved fields and no network channels.

## Variant odds

The planner lists each possible variant with its chance:

- Sheep mix wool colors through the dye recipes, so red and white always make a pink lamb. Colors without a recipe give either parent's color.
- Axolotls take a parent's color, except 1 time in 1,200 when the baby is blue.
- Mooshrooms take a parent's color. Two parents of the same color have a 1 in 1,024 chance of the other color.
- Pandas pass one of each parent's two genes, and each gene can turn random 1 time in 32. The odds are grouped by how the cub looks and which hidden gene it carries.
- Horses keep a parent's coat 4 times in 9 each and get any coat 1 time in 9. Markings work the same way with 2 in 5 for each parent.
- Llamas, foxes, and the warm and cold cows, pigs, and chickens of 1.21.5 and newer take either parent's variant, half the time each. Cats and wolves do too.
- Rabbits take a parent's coat 19 times in 20. The rest of the time the biome where the baby is born picks the coat, and the planner shows that share as decided by the biome.

Frogs are left out, because a frog's color depends on the biome where its tadpole grows up. Animals from other mods are left out because Family Tree can't read their rules.

## How two animals are related

Shift-click a second card in the tree. The panel names the relationship in plain words, such as "Quill and Sorrel are half siblings" or "Aspen and Briar are first cousins", and the cards and links between them light up. Shift-click the card again to stop comparing. Family Tree says "not related as far as Family Tree knows" when the history has no shared ancestor.

The planner shows the same sentence and the foal's inbreeding coefficient, such as 25% for full siblings and 12.5% for half siblings. Vanilla Minecraft ignores inbreeding, so this is information, not a penalty. **Show relationship** opens a tree with just the two animals and the ancestors that connect them.

## Best pairs

**Best pairs** ranks pairs of living adult horses, donkeys, mules, or llamas by the foal's expected speed, jump, health, chest slots, or an overall score. The overall score averages each stat as a share of the game's range. Filters skip close relatives, whose foal would be 1/8 inbred or more, or every known relative, and keep pairs to one owner or to your own animals. Click a pair to open it in the planner. In a test with 400 horses, ranking took about a tenth of a second.

## Players without the client mod

`/familytree breed <a> <b>` prints the prediction and the relationship in chat, using the same name and UUID rules as the other commands. In the chest menu, a pet's family page has **Plan breeding**, which lists possible mates and opens the plan as a book. Both use only animals the player may view.

The family page also has **Show relatives nearby**. It lists the pet's relatives loaded within 64 blocks in chat, with the same labels as the key, and puts a column of colored dust over the pet and each relative. Only the player who pressed it sees the dust, and clients without the mod show it too.

## Permission nodes for LuckPerms

Server owners can now decide who may do what with LuckPerms or another permission mod. Family Tree checks a `familytree.*` node for every command and action, such as `familytree.rename`, `familytree.locate`, `familytree.parents`, `familytree.others.view` for browsing everyone's pets, `familytree.others.manage` for editing them, `familytree.prune`, and `familytree.breed`. [Family Tree on servers](../servers.md#permission-nodes) lists all 14.

- It uses fabric-permissions-api on Fabric, which LuckPerms includes, and PermissionAPI on NeoForge and Forge.
- Without a permission mod, or when a node is unset, players get what they got in 1.3.0 by operator level. Nothing changes until an admin sets a node.
- A command a player's nodes deny answers with the node it needs, such as "You don't have permission for that (familytree.locate)", and chest menu buttons disappear when their action is denied. The `/familytree` usage line lists only the subcommands the player may run, and the key hint leaves out `/familytree menu` when the player can't open the chest menu.
- Fabric doesn't need fabric-permissions-api installed. Family Tree only uses it when a permission mod brings it.

## Server settings with comments and reload

`config/familytree-server.properties` now explains every setting in a comment above it, with its default and allowed values. `/familytree reload` reads the file again without a restart and names each value Family Tree can't use, in the log and in the admin's chat, with the value it uses instead. A misspelled setting stays in the file under "Not recognized" so the typo isn't lost. `/familytree settings` lists what differs from the defaults.

New settings, all with 1.3.0's behavior as the default:

- `operatorLevel` sets which permission level counts as an operator.
- `ownersCanLocate`, `ownersCanRename`, `ownersCanEditParents`, and `ownersCanSetAge` can leave those actions to operators.
- Six cooldowns: opening the screens and menu, a player's scans, scans across the server, locating, edits, and the relatives key.
- `listLimit` for `/familytree list`.
- `linkingStick` turns the linking stick off, `linkingStickName` changes the name it needs, and `linkingSelectionSeconds` sets how long it remembers a selection.
- `serverLanguage` answers every player in one language, including players who have the client mod.
- `farmLimitMessage` and `locateTeleportLink` turn off those chat messages.
- `discoverPetsOnLoad=false` stops tamed pets from joining the history just because their chunk loaded.

A 1.3.0 settings file loads unchanged. Family Tree rewrites it once to add the new settings and the comments.

## Choose species with datapacks

Modpacks can add species to the `familytree:tracked` and `familytree:ignored` entity type tags from a datapack or KubeJS. The server's settings file wins when they disagree, and both win over the farm, wildlife, and modded switches. [Family Tree on servers](../servers.md#datapack-tags) has an example.

## Tested on servers

Family Tree ran on dedicated Fabric 1.21.11, NeoForge 1.21.1, and Forge 1.20.1 servers with a modded and an unmodded client joined at once, and with LuckPerms on Fabric 1.21.11 and 26.3, NeoForge 1.21.11 and 26.3, and Forge 1.20.1. The servers also ran spark, Lithium or Canary, FerriteCore, ModernFix, C2ME, Krypton, Chunky, ServerCore, No Chat Reports, and Clumps where those have builds. [Family Tree on servers](../servers.md#tested-servers) lists the versions and results.

With 5,000 farm animals in the history, Family Tree used 0.4% of the server thread while two players opened its screens, saved, and scanned, and its records took under 1 MB of memory.

LuckPerms 5.4.140, the last LuckPerms for NeoForge 1.21.1, disconnects every player at login on the NeoForge versions Family Tree supports, with or without Family Tree. On NeoForge 1.21.1, Family Tree keeps using operator levels.

## Multiplayer fixes

- When two players fed the two parents, both parents and the baby went to one of them. Now each parent belongs to the player who fed it, and the baby to the first parent's owner, as before. This includes camels, which kept going to the first player in earlier builds of this release, and a parent whose feeder logs off before the animals breed.
- A player without the client mod and without the chest menu saw `key.familytree.open_tree` in the help text. The key hint now goes only to players with the mod.
- A player without the client mod got every linking stick message twice, and the first click said the animal was already selected.
- The cooldown message no longer says "two seconds", since the cooldowns are settings now.

## Paper and Spigot servers

Family Tree now comes as a plugin for Paper, Spigot, and Paper forks such as Purpur. Put `familytree-1.4.0+plugin.jar` in `plugins/`, and players type `/familytree` for the chest menus without installing anything.

- One jar runs on Paper from 1.20.1 to 26.3 and on Spigot 1.20.1, 1.21.11, and 26.3. Each version in [the guide](../plugin.md#supported-servers) was tested with a real server and an unmodded client.
- It records the same animals as the mod: tamed pets on their own, and other animals once a player breeds, names, or adds them with the linking stick. Deaths, horse stats, and variants are recorded too.
- It has the mod's `/familytree` commands, including `breed`, `reload`, and `settings`, the chest menus with search, rename, Add parents, the family book, Plan breeding, and **Show relatives nearby**, and the `familytree.*` permission nodes for LuckPerms.
- `plugins/FamilyTree/config.yml` has the mod's server settings under the same names, each with a comment.
- History stays in the mod's `familytree.dat`, in the same place and format. A world keeps its families when a server moves between the mod and the plugin.
- Players who have the Family Tree client mod get its screens and the relatives key on a plugin server. The browser, trees, rename, Locate, and Find existing pets were tested with the 1.3.0 Fabric client on Paper 26.3. The relatives key was tested with the Fabric client on Paper, Purpur, and Spigot, with NeoForge 1.21.1 and 26.3 on Paper, and with Forge 1.20.1 on Paper.
- On Spigot, item names in the menus show species names in English, and Spigot 1.20.1 asks for search and rename text in chat. Paper shows everything in the player's language and uses an anvil. [Differences from the mod](../plugin.md#differences-from-the-mod) lists the rest.

## Big farms, large litters, and long lines

- A species view with more than 40 animals now shows its families a page at a time, largest family first, with **<** and **>** to turn pages and a label such as "Families 1–38 of 241". Before, 1,250 sheep fit to 0% and drew as one line, and 250 cats fit to 9% as empty outlines. Now a page of cats fits at 29% with names and faces. A family larger than a page gets a page of its own.
- **Find by name** in a species view jumps to the first animal whose name contains the text, on whatever page it is, and Enter moves to the next match.
- **Fit tree** stops at 25%, where cards still show names. When the family doesn't fit, it centers on the selected animal, or starts at the first card in the top row. Scrolling out stops at 10%, which still shows the shape of a family of 1,245 sheep.
- A generation with more than 10 animals wraps into rows, so a pair with 45 puppies opens at a readable size and exports. Links into a wrapped generation run down its left side and links out of it down its right side, so no line passes under a card.
- A parent's tree now shows each foal's other parent beside it, linked to the foal, so a foal no longer looks like it had one parent. Hiding the parent's branch hides that card too.
- A tree still opens with six generations above and below the animal. When there are more, the edge cards get a ▲ or ▼ tab with the number of generations left out, such as "▲ +18" on a 25-generation line. Click the tab to show six more. Exported images carry the same marks.
- At 854x480, Minecraft's default window, and other short windows such as 1080p at GUI scale 4, the tree's buttons move to a column beside the tree. In testing, a cow's tree that fit to 12% at 854x480 now fits at 45%.
- In a species view too large for one image, export says how many animals the family has and suggests exporting one animal's tree.
- Exported images are named after the animal or species and the date, such as `family-tree-Comet-2026-10-31.png`, with `-2` and so on for later exports that day. Before, the name had a random number.

## Fixes

- **Show all** no longer moves the tree. The selected card, or another card when nothing is selected, stays where it was.
- On Minecraft 1.21.9 and newer, the Controls screen named Family Tree's key category `key.category.familytree.familytree`. It now says Family Tree.
- A player who may not locate, because of `ownersCanLocate=false` or a denied `familytree.locate`, no longer receives their pets' last known positions with the family list or in the reply to a rename. Neither does a player who may manage other players' pets but not locate them.
- `/familytree locate`, `pair`, `unpair`, `setage`, `setbirth`, and confirming the linking stick now wait for the locate and edit cooldowns, like the screens and the chest menu.
- `/familytree info` counts generations only through animals the player can see, so it matches the screens and tooltips.
- `/familytree info` with a name two pets share listed the choices and then said "No record". It now lists the choices only, and each choice can be clicked to fill in the command with that pet's UUID.
- Locating or editing another player's pet that you can see now says only its owner or an operator can do that, instead of "No record". A pet you can't see still prints "No record" once, not twice.
- Quoted names such as `/familytree info "Treename Test"` now work in `info` and `locate`.
- A rename refused by `familytree.rename` now names the permission on the rename screen and in the chest menu, instead of saying only the owner or an operator can rename the pet.
- `/familytree list` no longer repeats an animal's name inside its death message. Locate names the dimension, such as "in the Overworld", and reports a dead animal's last known location in one line.
- "Set Rex to 1 days old" and "Found 1 problem(s)" now read "1 day old" and "Found 1 problem". `/familytree reload` no longer counts the note about command aliases waiting for a restart as a problem.
- Linking a pig or another animal into its own ancestry now says "An animal can't be its own ancestor" instead of calling it a pet.
- Bred foxes are recorded. Since 1.3.0, a fox kit and its parents never joined the history, because foxes breed through their own code instead of the path every other animal takes. Now the kit and both parents join for the player who fed them sweet berries or glow berries, on every loader and the Paper plugin.
- Breeding turtles adds both parents for the player, as breeding frogs and sniffers does. Baby turtles still hatch from eggs without parents, so name or add them and use **Add parents**.
- Riding a camel or a skeleton trap horse no longer adds it to the history when the server ignores its species through `ignoredSpecies` or the `familytree:ignored` tag. The mod and the plugin both had this.
- A death with no attacker, such as thorns damage from `/damage`, showed "%1$s was killed while trying to hurt %2$s". It now says the animal died. An animal shot by a dispenser's arrow is "shot by Arrow", as in Minecraft's own death message, instead of the same raw text.
- `/familytree setage`, `setbirth`, and their help now say what a world day is: 20 minutes of the world running. Ages still count those days, so sleeping and `/time` don't age animals, and existing birth days keep their meaning.
- With Jade's Horse Stats or WTHIT's horse lines on, the Family Tree tooltip no longer repeats a horse's speed and jump, or a llama's strength in Jade. It still shows health and the parent comparisons for the rest. Turn those off in Jade or WTHIT to get Family Tree's speed and jump lines back.
- At GUI scale Auto on a 1920x1080 screen, the browser's buttons took most of the height and the pet list showed half a row. The list now keeps at least two full rows at every GUI scale. Buttons are as wide as their labels, species buttons share one row that you page through with the arrows, and on the smallest screens Getting started, Settings, Refresh, and Send feedback move into a **More** button.
- Long rows no longer run into the day column, and the Breeding planner button fits its label in every language.
- Species buttons use the game's name for every species, so "Dogs", "Cats", and "Parrots" no longer sit next to "Camel" and "Horse".
- Search used to look only in the selected tab. When other tabs have matches, the list now says how many, and clicking that line shows them.
- **Find existing pets** now says how many new pets it found, that it found none nearby, or that the server didn't scan because you pressed it too soon.
- **Add parents** offers only animals that can be the parents: the pet's species, a horse and a donkey for a mule, and none of the pet's own descendants. Before, the server refused other choices only after Confirm. Rows in the pet picker start with the portrait and name.
- Escape goes back one screen everywhere, as it does in vanilla's Statistics and Advancements screens. Settings used to close Family Tree instead. Choosing a pair in Best pairs now returns to the planner instead of opening a second one.
- In Japanese, Chinese, and Korean, Getting started breaks lines between characters and keeps "Family Tree" on one line. It names the relatives key as "` (the key left of 1)" instead of a lone backtick.
- The hint and error text in Add parents is centered under the title, like the buttons.

## Upgrading a server

Permission nodes, the new settings, and the species tags add no saved fields and no network channels. A 1.3.0 settings file keeps every value.

The rename reply has one new status for a denied `familytree.rename`. The server sends it only to 1.4.0 clients, which it recognizes by the relatives channel. A 1.3.0 client gets the 1.3.0 reply and a chat line that names the node.
